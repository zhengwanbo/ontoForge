## Docker 单容器部署：后端先启动，再由 Nginx 承载前端

### 背景

前一天补齐的 Docker 方案采用两个服务：一个后端容器，一个前端容器。后续部署希望进一步简化为单容器模式，即前后端共同打入一个镜像，启动时先拉起 FastAPI 后端，再由 Nginx 对外提供前端页面并反代 `/api`。

### 改动文件

- `Dockerfile`
- `docker-compose.yml`
- `docker/nginx.conf`
- `docker/start.sh`

### 实施内容

- 将根目录 `Dockerfile` 调整为单一运行时 target：
  - 保留 `node:22-alpine` 前端构建阶段
  - 最终运行阶段改为 `python:3.11-slim`
  - 在最终镜像内安装 `nginx` 与 `curl`
  - 拷贝后端代码、前端构建产物、Nginx 配置与启动脚本
- 新增 `docker/start.sh`：
  - 后台启动 `uvicorn app.main:app --host 127.0.0.1 --port 8000`
  - 轮询 `/health` 直到后端可用
  - 后端健康后以前台方式执行 `nginx -g "daemon off;"`
  - 对 `INT/TERM/EXIT` 增加清理逻辑，避免后台 Uvicorn 进程残留
- 调整 `docker/nginx.conf`：
  - `/api/` 与 `/health` 由原先代理到 Compose 服务名 `backend:8000`
  - 改为代理到同容器内的 `127.0.0.1:8000`
- 简化 `docker-compose.yml`：
  - 从双服务改为单服务 `app`
  - 统一映射 `${APP_PORT:-8080}:80`
  - 健康检查改为访问容器内 `http://127.0.0.1/health`
  - 保留 `host.docker.internal:host-gateway`，便于容器内访问宿主机 Oracle

### 验证结果

- `docker-compose config`：通过，确认单服务编排、环境变量替换与健康检查语法正确。
- `sh -n docker/start.sh`：通过，启动脚本语法正确。
- `docker-compose build app`：
  - 已进入 BuildKit 并开始解析新的单容器 `Dockerfile`
  - 在拉取 `node:22-alpine` 与 `python:3.11-slim` 基础镜像时失败
  - 当前报错为 Docker 拉取链路的 TLS 证书信任问题：
    - `tls: failed to verify certificate: x509: certificate signed by unknown authority`
  - 说明当前阻塞点是本机 Docker/镜像仓库证书配置，不是仓库内新增 Docker 文件的结构错误

### 遗留问题

- 若部署环境中的 Oracle 不在宿主机，需要在启动前覆盖 `DATABASE_URL`，不能直接沿用默认 `host.docker.internal`。
- 单容器方案仍依赖目标环境能正常访问 Docker Hub 或已配置可用的镜像加速/私有仓库。
- 当前本机 Docker 拉取镜像存在证书信任异常，构建前需先修复宿主机 Docker 的 CA 或 registry 配置。

### 下一步建议

- 在目标服务器执行前，先确认 Docker 能正常拉取 `node:22-alpine` 与 `python:3.11-slim`。
- 使用 `docker-compose up -d --build` 启动单容器版本；访问入口为 `http://<host>:8080`。
