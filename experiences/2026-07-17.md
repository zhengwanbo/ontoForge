# 2026-07-17

## 背景
- 用户要求后端在访问对象数据库（例如“缺陷分析数据”对应的 `oonbuild` schema）时，必须输出：
  - 执行 SQL
  - SQL 参数
  - 查询结果预览
  - 异常日志
- 不能只看到应用元数据库 `sys_*` 的 SQLAlchemy 查询日志。

## 改动文件列表
- `backend/app/services/source_data_service.py`
- `backend/app/api/datasource.py`
- `experiences/2026-07-17.md`

## 具体改动

### 1. SourceDataService 补齐对象数据库原生日志
- 在 `backend/app/services/source_data_service.py` 中新增统一日志包装：
  - `_execute_remote_sql(...)`
  - `_fetchall_logged(...)`
  - `_fetchone_logged(...)`
- 覆盖场景：
  - 查询当前连接用户
  - 查询 schema 列表
  - 查询远程表列表
  - 查询表结构
  - 查询表注释
  - 查询样例数据
- 现在只要执行到了对象数据库查询，就会输出：
  - `REMOTE SQL execute: ...`
  - `REMOTE SQL params: ...`
  - `REMOTE SQL result: ...`
  - `REMOTE SQL failed: ...`

### 2. datasource.py 直连业务库链路也补齐日志
- 在 `backend/app/api/datasource.py` 中新增同样的原生 SQL 日志包装。
- 覆盖场景：
  - 测试数据源连接
  - 数据源管理页查询表列表
  - 数据源管理页查询表结构
  - 查询表注释
- 这样“系统管理 > 数据源管理”的业务库访问日志与“数据映射”的对象数据库访问日志格式保持一致。

## 验证结果
- 后端语法检查：
  - `cd backend && python -m py_compile app/services/source_data_service.py app/api/datasource.py`
  - 结果：通过。

## 注意事项
- 如果连接在 SQL 执行前就失败，只会看到：
  - `Connect to Oracle source ...`
  - `Connect to Oracle source failed ...`
- 这表示还没有进入 `REMOTE SQL execute` 阶段，不是日志缺失，而是对象数据库连接阶段就已经中断。
