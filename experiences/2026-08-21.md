## 前端 Nginx 部署配置

### 背景

为 Vue/Vite 前端提供可供生产环境引用的 Nginx `server` 配置，并将同源的 `/api/v1` 请求代理到 FastAPI。

### 改动文件

- `ontoforge-front.conf`

### 实施内容

- 配置前端构建目录 `/opt/ontoforge/frontend/dist` 作为站点根目录。
- 使用 `try_files` 将 Vue Router 的前端路由回退到 `index.html`。
- 对带指纹的静态资源启用一年不可变缓存，对入口 HTML 使用 `no-cache`。
- 将 `/api/` 和 `/health` 保持原始路径代理到 `127.0.0.1:8000`，并为 DDL、LLM 等长耗时请求设置 10 分钟代理超时。

### 验证结果

- 本机 Nginx 版本：`1.27.3`。
- `git diff --check`：通过。

### 部署说明

- 部署时需按实际发布目录、域名和 HTTPS 证书调整 `root`、`server_name` 及 TLS 配置。

## 业务规则活动中的指标定义

### 背景

需要在“业务对象构建 > 业务规则活动”中先维护本体对象的业务指标口径，例如有效客户、有效收入和可用库存，再配置基于指标的业务规则和后续活动。

### 改动文件

- `backend/app/models/models.py`
- `backend/app/schemas/schemas.py`
- `backend/app/api/business_rules.py`
- `frontend/src/api/index.ts`
- `frontend/src/views/business/BusinessRulesActivities.vue`

### 实施内容

- 新增 `sys_metric_definition`，按分析域和本体对象保存指标编码、名称、类别、口径说明、计算表达式、聚合方式、统计周期、单位、阈值 JSON 与启用状态。
- 新增指标定义 CRUD API，并校验用户的分析域权限、关联本体对象归属和同域指标编码唯一性。
- “业务规则活动”新增首个“指标定义”页签，支持按当前分析域选择本体对象、新增、编辑和删除指标；业务规则和业务活动页签维持原功能。
- 指标编辑表单提供有效客户、有效收入、可用库存等场景所需的口径、计算表达式和阈值配置输入项。

## Guide 本体生成流程分阶段改造

### 背景

原 Guide 将文档解析、数据表识别、映射设计和物理部署绑定为一次操作，无法支持仅有业务文档的企业先完成高层本体设计和逻辑确认、后续再接入数据资产的工作方式。

### 改动文件

- `backend/app/schemas/schemas.py`
- `backend/app/api/ontology.py`
- `backend/app/services/ontology_guide_service.py`
- `backend/app/services/llm_service.py`
- `frontend/src/api/index.ts`
- `frontend/src/views/ontology/OntologyBuild.vue`

### 实施内容

- Guide 首步新增三种生成阶段：文档先行逻辑设计、数据补全并落地、一体化生成（兼容原流程）。
- 文档先行阶段不要求数据源、DDL 或关联表；根据业务文档和已选业务语义模式生成高层本体设计文档、初版逻辑实体、属性和关系，并明确禁止大模型虚构表、字段、Join 与 SQL。
- 逻辑确认只创建本体定义，不创建映射种子；蓝图状态从 `LOGICAL_DRAFT` 更新为 `LOGICAL_CONFIRMED`。
- 新增 Guide 蓝图列表接口。数据补全阶段仅能选择当前分析域内已确认的逻辑蓝图作为基线。
- 数据补全阶段强制使用 LLM 语义补全路径，并在结果中保留确认基线；物理字段映射优先，未识别的逻辑实体、属性和关系再由基线补回，避免数据补全时静默遗漏人工确认内容。
- 前端在文档先行阶段隐藏数据表和规则表操作区及部署步骤，数据补全阶段展示逻辑基线选择并执行相应校验。
- Guide 首次进入仅显示“资料输入”；生成预览后才按阶段展示可用的“分析确认”“本体浏览”“视图应用”。文档先行路径不显示“视图应用”。
- Guide 首屏进一步改为独立的“选择本次本体生成执行方式”，提供文档先行逻辑设计、基于逻辑基线的数据补全和一体化生成三项；用户确认执行方式后才进入“资料输入”及其步骤导航。
- 文档先行且使用 LLM 模型辅助时，生成策略由 MVP 收敛改为“文档语义完整覆盖”：高层设计、实体和关系提示词要求覆盖文档明确对象及可由事件、层级、生命周期、指标、规则、案例直接推断的对象关系；取消对该阶段实体和关系的 MVP 二次过滤，保留人工后续确认和删减空间。
- LLM 提示词中的制造缺陷模板改为由所选业务语义显式开关控制；营销、供应链及其他非制造缺陷语义不会发送 SFR、缺陷、规格上下限、根因或测试工站相关要求。仅选择制造缺陷语义模式（测量阈值判定或案例根因闭环等）时才注入对应专用规则。
- 新增“缺陷根因分析业务语义”（`MANUFACTURING_DEFECT`），其业务语义描述集中维护制造质量特征、规格判定、缺陷事件、过程追溯、历史案例、根因验证和改善闭环；结构化领域生成的原“SFR根因分析 / 缺陷分析”合并为此唯一选项，历史请求会自动兼容归一。结构化生成自动加载该业务语义，LLM模型辅助不再使用制造缺陷专用提示。
- 结构化领域生成的业务语义选择改为复用“业务语义管理”接口和下拉交互，不再在 Guide 写死语义选项。只有在管理中同时配置“质量规则与缺陷判定”（`measurement-threshold-violation`）和“根因分析与改善闭环”（`case-rootcause-action`）模式的启用业务语义，才可被结构化领域生成选择；后端按同一配置校验。
- 修复营销语义提示词污染：`business_summary` 不再仅因文档出现 SFR/缺陷关键词就生成制造缺陷追溯路径。只有当前选择的业务语义为 `MANUFACTURING_DEFECT` 时才构造质量缺陷专用摘要；其他语义使用业务主体、事件、规则指标、生命周期及交易/服务结果的通用摘要。
- 文档先行流程拆为两阶段：先生成并持久化 `LOGICAL_DESIGN_DRAFT` 高层本体设计文档，用户在 Guide 的“分析确认”中查看并确认范围边界、对象定义及候选标识、逻辑关系、生命周期/事件/指标/规则、确认与假设项及所需数据表类型；点击确认后才基于已确认设计生成逻辑实体、属性和关系，并将设计蓝图标记为 `LOGICAL_DESIGN_CONFIRMED`。高层设计提示词与结果新增对应结构化字段。
- 修复高层设计确认页面回退为旧预览的问题：最新蓝图读取接口补充返回 `generation_phase`，前端在刷新后保留接口直接返回的阶段字段，确保 `design` 阶段展示完整高层设计确认内容。
- Guide 按产品术语将“生成高层本体设计文档 / 确认高层设计并生成本体对象”调整为“生成本体设计文档 / 确认设计并生成本体对象”。逻辑本体生成蓝图持久化 `source_design_blueprint_id` 与版本号，最新蓝图和 Guide 蓝图列表接口均返回该来源信息，前端预览可显示来源设计文档，支持后续追溯。
- Guide 文档上传解析改为 Markdown 优先：原始 `.md` 内容直接保留，`.docx` 使用 `python-docx` 提取标题、列表和表格并转换为 Markdown，`.txt/.pdf` 转为基础 Markdown；接口同时保留兼容 `text` 字段并新增 `markdown`、`content_format`，前端将 Markdown 写入业务说明框供后续设计文档和本体生成使用。
- 修复本地运行环境缺失 DOCX 解析依赖：在当前后端 Python 环境安装 `python-docx==1.2.0` 及 `lxml`，并确认 `from docx import Document` 可正常导入（版本 `1.2.0`）。
- 修复 Oracle `SYS_ONTOLOGY_BLUEPRINT.STATUS VARCHAR2(20)` 溢出：文档先行设计确认后的状态从 24 字符的 `LOGICAL_DESIGN_CONFIRMED` 改为 19 字符的 `LOGICAL_DESIGN_DONE`，并在蓝图状态写入前增加 20 字符长度校验，避免再以 Oracle ORA-12899 形式暴露。
- Guide 入口改为两层生成方式：一级为“一体化生成 / 分步骤生成”，二级仅在分步骤时选择“本体逻辑设计 / 数据补全设计”。界面仍映射到兼容的 `integrated / document_first / data_enrichment` 后端阶段：逻辑设计仅需需求文档并先生成、确认高层本体设计文档；数据补全强制选择已确认逻辑蓝图并输入业务数据对象。数据补全结果新增属性来源和关系来源建议表，方便后续进入数据映射。
- 修复 Guide 初始入口下资料区提前展示：资料输入、分析确认、本体浏览和视图应用步骤统一要求先点击“进入一体化生成”或“进入分步骤生成”后才渲染，避免用户仅切换生成方式时就看到数据表、DDL 和文档输入区。

### 验证结果

- `python -m py_compile backend/app/schemas/schemas.py backend/app/api/ontology.py backend/app/services/ontology_guide_service.py backend/app/services/llm_service.py`：通过。
- `frontend/npm run build`：通过；仅保留既有的大包体积提示。
- `git diff --check`：通过。
