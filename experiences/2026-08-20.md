## 用户与业务分析域授权

### 背景

系统需要支持由管理员为新用户分配可查看和使用的业务分析域；非管理员登录后不得通过页面选择或直接调用接口读取、修改未授权域的本体、数据映射、DDL 和其他分析域内容。`admin` 用户保持全域管理能力。

### 改动文件

- `backend/app/models/models.py`
- `backend/app/core/auth.py`
- `backend/app/schemas/schemas.py`
- `backend/app/api/system.py`
- `backend/app/api/domains.py`
- `backend/app/api/ontology.py`
- `backend/app/api/mapping.py`
- `backend/app/api/ddl.py`
- `backend/app/api/ontology_browse.py`
- `backend/app/api/source_data.py`
- `backend/app/api/process.py`
- `backend/app/api/business_rules.py`
- `backend/app/api/agent.py`
- `frontend/src/views/system/SystemManage.vue`

### 实施内容

- 新增 `sys_user_domain_permission` 用户-分析域授权表，使用用户 ID 和分析域 ID 作为联合主键；服务启动时由既有 `Base.metadata.create_all` 自动创建。
- `admin` 角色的授权查询返回全域权限，不需要也不会保存冗余的分析域授权记录。
- 用户管理接口的创建、编辑和列表响应支持 `domain_ids`；非管理员必须至少分配一个有效业务分析域。
- 用户管理页新增“可用业务分析域”多选控件和授权域列表展示；管理员显示“全部分析域”。
- 分析域列表对非管理员只返回已授权域；本体、映射、DDL、图谱浏览、图查询、流程、业务规则和智能体相关接口在域 ID、实体 ID、关系 ID、任务 ID 或 DDL 日志 ID 的入口处执行服务端授权校验。
- DDL 历史列表也按授权域过滤，因此无法通过不传 `domain_id` 的方式查看其他域执行记录。

### 验证结果

- `python -m py_compile`（涉及的认证、模型、Schema 及 API 模块）：通过。
- `frontend/npm run build`：通过。
- `git diff --check`：通过。

### 遗留问题与下一步建议

- 已有非管理员用户不会自动获得历史分析域授权，管理员需要在“系统管理 > 用户管理”中编辑用户并勾选其可用域。
- 若将来增加新的、携带 `domain_id` 的业务接口，应复用 `ensure_domain_access`，保持同一授权边界。
