## 背景

- 该功能需要基于大模型理解当前分析域下已有实体、属性和关系，先生成调整建议，再允许用户确认后应用。

## 具体改动

### 1. 后端新增自然语言本体调整能力
- 在 `schemas.py` 中新增：
  - `OntologyNaturalAdjustRequest`
  - `OntologyNaturalAdjustApplyRequest`
- 在 `ontology.py` 中新增两个接口：
  - `POST /domains/{domain_id}/guide/natural-adjust`
    - 根据自然语言描述和当前分析域上下文生成调整计划
  - `POST /domains/{domain_id}/guide/natural-adjust/apply`
    - 应用前端确认后的调整计划，避免二次生成导致计划漂移

### 2. LLM 服务新增“调整计划”提示词与结果归一化
- 在 `llm_service.py` 中新增 `generate_ontology_adjustment_plan`。
- 输入给模型的上下文包括：
  - 当前业务分析域名称与说明
  - 当前选中实体（如有）
  - 当前分析域下已有实体及属性
  - 当前分析域下已有关系
  - 操作员输入的自然语言调整说明
- 约束模型输出严格 JSON，并归一化为三类动作：
  - `entityActions`
  - `propertyActions`
  - `relationActions`
- 同时对实体名、属性名、构建方式、关系类型做了规范化处理，减少模型脏输出直接进入应用阶段。

### 3. 新增本体调整应用服务
- 新建 `ontology_adjustment_service.py`，将“生成计划”和“应用计划”从路由中拆开。
- 应用阶段支持：
  - 实体 `create / update / delete`
  - 属性 `create / update / delete`
  - 关系 `create / update / delete`
- 应用时会优先按 `ID` 定位，若模型未返回有效 `ID`，再按实体名、属性名、关系名回退匹配。
- 删除属性时会同步删除属性映射，并刷新实体映射状态，避免遗留“实体仍显示已映射”的脏状态。
- 创建新实体时会自动分配图上初始位置，保证落库后图视图可见。

### 4. 前端页面新增“自然语言调整”入口与交互
- 在 `OntologyBuild.vue` 的本体关系图工具栏新增 `自然语言调整` 按钮。
- 新增独立弹窗，包含：
  - 当前分析域和当前选中实体提示
  - “仅调整当前选中实体”开关
  - 模型选择
  - 自然语言说明输入框
- 用户点击“生成调整计划”后，页面展示：
  - 调整总结
  - 对象调整列表
  - 属性调整列表
  - 关系调整列表
- 用户点击“应用调整计划”后：
  - 调用独立 apply 接口应用当前预览计划
  - 刷新本体图
  - 若之前是针对当前选中实体调整，尽量恢复该实体选中态
  - 把后端返回的 warning 展示在预览区

### 5. 前端 API 补充
- 在 `frontend/src/api/index.ts` 中新增：
  - `graphApi.naturalAdjustOntology`
  - `graphApi.applyNaturalAdjustOntology`

## 补充具体改动

### 6. 批量全域映射改为后台异步任务
- 保留原有 `sys_mapping_task` 任务表，不新增新表。
- 将 `POST /mapping/domains/{domain_id}/bulk-auto-mapping` 改为：
  - 先创建一条 `BULK_GENERATE` 任务记录
  - 初始状态写为 `IN_PROGRESS`
  - 立即返回 `task_id`，不再等待全量映射执行完毕
- 后端随后通过后台线程启动独立任务，使用新的数据库会话执行原有批量映射逻辑。

### 7. 后端任务执行过程中持续回写进度
- 在 `mapping.py` 中新增任务更新辅助逻辑。
- 后台任务每处理完一个本体对象，都会更新：
  - `status`
  - `summary_json`
  - `result_json`
- 当前进度摘要新增字段：
  - `processed_count`
  - `running`
  - `current_entity_name`
- 任务结束后状态会更新为：
  - `SUCCESS`
  - `PARTIAL`
  - `FAILED`

### 8. 防止同分析域重复提交多个后台全域映射任务
- 新增校验：
  - 若当前分析域已有 `BULK_GENERATE + IN_PROGRESS` 任务，则不再重复创建新任务
  - 直接返回已有 `task_id`
- 这样可以避免同一分析域被反复触发多个高耗时后台映射线程。

### 9. 前端页面增加“后台映射工作”状态区
- 在 `DataMappingOperation.vue` 的左侧配置区新增后台任务面板。
- 面板展示：
  - 任务号
  - 当前状态
  - 总对象数
  - 已处理对象数
  - 已生成建议数
  - 失败对象数
  - 当前正在处理的对象名
  - 进度条
- 并提供：
  - `刷新状态`
  - `载入结果`

### 10. 前端改为轮询任务进度并自动载入完成结果
- 点击“生成全域映射建议”后：
  - 页面只提交任务，不再长时间阻塞等待接口
  - 保存 `task_id`
  - 自动开启 5 秒轮询
- 轮询读取任务详情后：
  - 若任务仍在执行，则持续刷新状态卡片与历史列表
  - 若任务完成，则自动停止轮询
  - 成功或部分成功时自动把结果载入当前工作区
  - 失败时给出错误提示

### 11. 历史任务列表同步显示进度信息
- “批量映射历史”卡片中的每项任务摘要新增：
  - `Processed: 已处理 / 总对象`
- 这样即使用户刷新页面或离开后再回来，也能从历史区直接看到后台任务是否仍在执行。

## 补充遗留问题
- 当前异步任务仍运行在应用进程内的后台线程中。
  - 如果服务进程重启，正在执行的任务不会自动恢复。
  - 任务记录会保留，但状态可能停留在 `IN_PROGRESS`。
- 若后续任务量继续增大，建议迁移到专门的任务队列或调度器（如 Celery / RQ / 独立 worker）。

## 补充下一步建议
- 给 `sys_mapping_task` 增加“最后心跳时间”或“执行日志片段”，便于识别僵尸任务。
- 为后台任务补一个“取消任务”入口。
- 若部署为多实例，建议把后台任务执行从 Web 进程剥离，避免实例切换导致任务状态不一致。

### 12. 为远端 Oracle 读取增加断线重试能力
- 在 `SourceDataService` 中新增：

  - `get_remote_table_detail`
