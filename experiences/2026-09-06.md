# 2026-09-06

## Docker 一键部署：新增根目录 Dockerfile 与 docker-compose 编排

### 背景

项目当前已有后端 FastAPI 与前端 Vue 3/Vite 两套应用，但缺少容器化交付文件。后续需要通过 Docker 一键部署，因此需要在仓库根目录补齐统一构建与编排方案。

### 改动文件

- `Dockerfile`
- `docker-compose.yml`
- `docker/nginx.conf`
- `.dockerignore`

### 实施内容

- 新增根目录多阶段 `Dockerfile`：
  - `frontend-builder` 使用 `node:22-alpine` 执行 `npm ci` 与 `npm run build`
  - `backend` 使用 `python:3.11-slim` 安装 `backend/requirements.txt` 并以 `uvicorn app.main:app --host 0.0.0.0 --port 8000` 启动
  - `frontend` 使用 `nginx:1.27-alpine` 承载前端静态构建产物
- 新增 `docker/nginx.conf`：
  - 静态资源直接由 Nginx 提供
  - `/api/` 与 `/health` 代理到 Compose 内的 `backend:8000`
  - 保留 SPA 的 `try_files ... /index.html` 回退
- 新增 `docker-compose.yml`：
  - `backend` 与 `frontend` 两个服务均从同一个根目录 `Dockerfile` 构建不同 target
  - 前端暴露 `8080:80`，后端暴露 `8000:8000`
  - `frontend` 依赖 `backend` 健康检查
  - `backend` 默认将 Oracle 连接指向 `host.docker.internal:1521/freepdb1`，便于容器访问宿主机 Oracle
  - 增加 `extra_hosts: host.docker.internal:host-gateway`，兼容 Linux/Colima 一类环境
- 新增 `.dockerignore`，排除 `.git`、`frontend/node_modules`、`frontend/dist`、Python 缓存等无关构建上下文。

### 验证结果

- `docker-compose config`：通过，确认 Compose 语法、环境变量替换、`depends_on` 与健康检查配置均可解析。
- `docker version --format '{{.Server.Version}}'`：返回 `28.4.0`，确认本机 Docker daemon 可用。
- `docker-compose build backend frontend`：
  - 已成功进入 BuildKit 构建流程并开始解析 `Dockerfile`
  - 但在拉取 `python:3.11-slim` 基础镜像时出现 Docker Hub 网络超时：
    - `failed to do request: Head "https://registry-1.docker.io/v2/library/python/manifests/3.11-slim": dial tcp ...:443: i/o timeout`
  - 该失败属于外部镜像仓库网络问题，不是本次新增文件的语法或结构错误。

### 遗留问题

- Compose 默认的 Oracle 连接串指向宿主机 `host.docker.internal`；如果目标部署环境中的 Oracle 不在宿主机，需要在启动前覆盖 `DATABASE_URL`。
- 当前未将 Oracle 数据库本身纳入 Compose，因为仓库后端已强依赖 Oracle，且 Oracle 容器镜像、初始化与许可证约束不适合在本项目中直接捆绑。
- 基础镜像构建的最终成功仍取决于部署环境能访问 Docker Hub 或对应私有镜像仓库。

### 下一步建议

- 在实际服务器上执行前，先设置正确的 `DATABASE_URL`，再运行 `docker-compose up -d --build`。
- 如果部署环境无法访问 Docker Hub，应提前配置镜像加速器或将 `node:22-alpine`、`python:3.11-slim`、`nginx:1.27-alpine` 同步到内网仓库。
