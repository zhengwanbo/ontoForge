## DDL 生成关系边部署可靠性修复

### 背景
- SFR 缺陷分析域生成的 Oracle DDL 执行失败。脚本中可确认存在 `tgt` / `dst` 目标别名不一致、关系条件引用节点表未投影字段，以及同一语义视图被重复生成清理语句的问题。

### 改动文件列表
- `backend/app/services/ddl_service.py`
- `backend/tests/test_ontology_graph_mapping_design.py`
- `experiences/2026-07-31.md`

### 具体改动
- 关系 Join 条件兼容历史 `tgt.<column>` 写法，统一转换为实际 CTAS 使用的 `dst.<column>`。
- 基于属性映射把来源字段名转换为节点输出属性名。例如目标节点将源字段 `MODEL` 投影为 `MODEL_CODE` 时，关系条件会自动使用 `dst.MODEL_CODE`。
- 对显式关系条件做节点列校验；若仍引用未投影的字段（例如 `semantic_mapping_metric_name`），不生成该边表，也不将其加入 Property Graph，防止一个未完成映射导致整批 DDL 失败。
- Property Graph 统一使用实际生成的 `EDGE_ID` / `SOURCE_ID` / `TARGET_ID` 边表结构，且只引用可部署关系。
- 语义视图若本次会重建，不再额外生成“遗留视图清理”语句，移除重复 `DROP VIEW`。
- 对来源于 CTAS 的节点表，在建主键前删除空主键及重复业务主键记录，避免设备、测试等履历型源数据因同一实体键重复而导致 `ALTER TABLE ... ADD PRIMARY KEY` 失败。
- 属性图不再引用由 `edge_sql` 临时生成的边视图；统一引用本次创建的唯一 `ONTO_EDGE_*` 边表，避免中文关系名被清洗为同一个 `ONTO_EDGE_EDGE_V`、缺少 `EDGE_ID`、或在图中重复登记。
- 未确认的 LLM 语义视图 SQL 不再直接执行。系统将使用已选源表生成安全投影；只有标记 `sql_confirmed: true`（或 `mapping_status: CONFIRMED`）的视图才执行自定义 SQL，避免虚构列导致 `CREATE VIEW` 失败。
- `ONTO_EDGE_EDGE_V` 仅作为旧版遗留对象在重建时生成一次 `DROP VIEW` 清理语句；新 DDL 不再创建该视图，也不在 Property Graph 中引用它。已补充对应回归测试。
- 未确认的边视图 SQL 同样不再部署。它们常引用尚未由安全原表投影提供的标准化列；只有 `sql_confirmed: true` 或 `mapping_status: CONFIRMED` 的边视图才会被创建。
