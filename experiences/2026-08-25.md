## 平台首页 Dashboard

### 背景

平台登录后此前默认进入业务分析域管理，缺少一个面向当前业务分析域的总览页面，用户无法快速判断本体建设进度、映射完成度、DDL 阻断原因和下一步操作。

### 改动文件

- `backend/app/api/dashboard.py`
- `backend/app/main.py`
- `frontend/src/views/HomeDashboard.vue`
- `frontend/src/router/index.ts`
- `frontend/src/views/Layout.vue`
- `frontend/src/api/index.ts`

### 实施内容

- 新增 `/dashboard/domains/{domain_id}/overview` 聚合接口，受当前用户业务域权限约束，汇总数据源、实体、属性、关系、映射、DDL、设计包与最近任务。
- 首页置于左侧菜单最上方、源数据管理之前，并成为根路由登录后的默认页面。
- 首页使用全局当前业务分析域，提供建设概览指标、建设阶段、DDL 阻断项、关系节点概览和最近活动。
- 提供本体构建、数据映射、映射关系检查、DDL 生成和图数据查询快捷入口；阻断项可直接跳转到对应的数据映射配置。

## Graph SQL 格式化与 Oracle 预检

### 背景

已生成的 Graph SQL 曾出现 `ORA-40997: invalid path pattern expression`。此前只做字符串安全检查，无法识别 Oracle 对 `GRAPH_TABLE` 路径、标签和属性的实际语法限制。

### 改动文件

- `backend/app/services/source_data_service.py`
- `backend/app/services/llm_service.py`
- `backend/app/api/source_data.py`
- `frontend/src/views/browse/GraphDataQuery.vue`

### 实施内容

- 新增 Graph SQL 语法预检：在目标 Oracle 数据库、当前 Schema 下执行 `SELECT * FROM (<Graph SQL>) WHERE 1 = 0`，仅让 Oracle 编译语句而不读取业务数据，从而提前发现 ORA-40997、无效标签和无效属性。
- LLM 首次生成后逐条预检；发现错误会携带 Oracle 错误反馈重新生成一次完整六条场景。第二次仍不通过时不保存，避免无效 SQL 进入缓存。
- 旧缓存也会在展示前经过预检；不通过时不展示并提示用户重新生成。
- 提示词明确限制为 Oracle `GRAPH_TABLE` 基本路径语法，并要求多行缩进格式。
- 页面增加深色“Graph SQL 格式化预览”代码区，保留原编辑器供用户调整后执行。

### 验证结果

- `cd backend && python -m py_compile app/api/source_data.py app/services/source_data_service.py app/services/llm_service.py`：通过。
- `cd frontend && npm run build`：通过；仅保留既有构建产物体积提示。
- `git diff --check`：通过。

## 图数据查询场景显式生成与复用

### 背景

图数据查询页每次进入或切换属性图时都会调用大模型生成六条场景，重复消耗模型调用时间和成本，也会让同一属性图的查询建议不稳定。

### 改动文件

- `backend/app/models/models.py`
- `backend/app/api/source_data.py`
- `frontend/src/api/index.ts`
- `frontend/src/views/browse/GraphDataQuery.vue`

### 实施内容

- 新增 `SYS_GRAPH_QUERY_RECOMMENDATION` 持久化记录，按业务分析域、数据源、Schema、属性图保存六条业务场景与 SQL。
- 页面加载仅读取已保存记录，不再触发 LLM；首次没有记录时提示用户显式生成。
- 增加带魔法棒图标的“生成业务场景与 SQL”按钮；再次点击即显式重新生成并覆盖当前范围的缓存。
- 模型重新生成失败时保留此前已保存结果；没有历史结果才返回基于实时图结构的保底探索 SQL。

### 验证结果

- `cd backend && python -m py_compile app/models/models.py app/api/source_data.py app/services/llm_service.py app/services/source_data_service.py`：通过。
- `cd frontend && npm run build`：通过；仅保留既有构建产物体积提示。

## 图数据查询按业务分析域智能生成场景

### 背景

图数据查询页原先固定提供营销域的六个业务场景，切换至供应链、制造或其他业务分析域时仍会显示促销、窜货、费用 ROI 等不相关内容，且 SQL 可能引用当前属性图不存在的标签或属性。

### 改动文件

- `backend/app/api/source_data.py`
- `backend/app/services/source_data_service.py`
- `backend/app/services/llm_service.py`
- `frontend/src/views/browse/GraphDataQuery.vue`
- `frontend/src/api/index.ts`

### 实施内容

- 读取 Oracle `ALL_PG_*` 实际元数据时，补齐顶点和边的全部属性、边两端定义，并尝试通过 `DBMS_METADATA.GET_DDL` 获取属性图 DDL；数据库版本不支持该元数据类型时不影响查询页面使用。
- 新增按当前业务分析域、最近本体设计摘要、属性图 DDL、真实顶点/边和全部属性驱动的 LLM 场景生成，严格要求返回 6 条不同的只读 `GRAPH_TABLE` SQL，且仅可使用已提供的真实对象和字段。
- 对模型输出增加 SQL 安全与图名校验；模型无配置、超时或未产生 6 条有效 SQL 时，自动回退为从当前实时图拓扑构建的通用探索查询，避免展示其他业务域的固定场景。
- 页面改为“智能生成的业务图查询”，清楚标识“LLM 已生成”或“结构保底”，LLM 请求超时延长到 200 秒。

### 验证结果

- `cd backend && python -m py_compile app/api/source_data.py app/services/source_data_service.py app/services/llm_service.py`：通过。
- `cd frontend && npm run build`：通过；仅保留既有构建产物体积提示。
- `git diff --check`：通过。
