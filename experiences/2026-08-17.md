## DDL 后台异步执行

### 背景
- Oracle DDL 的实际执行时间可能超过前端请求超时阈值（例如 6000ms），同步等待会让页面误报失败并阻塞用户操作。

### 改动文件列表
- `backend/app/api/ddl.py`
- `frontend/src/api/index.ts`
- `frontend/src/views/ddl/DDLManage.vue`
- `experiences/2026-08-17.md`

### 具体改动
- DDL 执行请求先写入 `SysDDLLog`，状态设为 `RUNNING`，立即返回任务日志 ID。
- 使用 FastAPI 后台任务在线程池中执行实际 Oracle DDL，并使用独立数据库会话保存最终汇总、每条 SQL 的执行明细，以及本体和关系的部署状态同步结果。
- 新增 `GET /ddl/logs/{log_id}/status`，返回后台任务状态、耗时和已持久化的逐语句明细。
- DDL 页面提交后展示“后台执行中”，以 1.5 秒间隔轮询任务；完成后自动刷新 DDL 历史与当前本体部署状态。历史列表增加“执行中”标签。

### 验证结果
- `python -m py_compile backend/app/api/ddl.py` 通过。
- `cd frontend && npm run build` 通过（仅有既有 bundle 体积提示）。
- `git diff --check` 通过。

### 遗留问题与下一步建议
- 当前逐条 SQL 明细在整个任务结束后一次性写入历史；如需执行中的逐条实时进度，可在 `DDLService.execute_ddl` 中增加每条语句完成后的持久化回调。

## Oracle 26ai 本体节点与边视图优先部署

### 背景
- Oracle AI Database 26ai 支持以数据库视图作为 SQL Property Graph 的顶点和边对象。
- 本体节点和关系边通常是源业务数据的投影，不需要复制为 CTAS 表；应优先保持实时视图，仅在没有稳定图键时回退为表。

### 改动文件列表
- `backend/app/services/ddl_service.py`
- `backend/app/api/ddl.py`
- `experiences/2026-08-17.md`

### 具体改动
- DDL 模板生成时，含本体主键的节点默认生成 `CREATE OR REPLACE VIEW`；视图过滤空键，并通过窗口函数按主键保留唯一节点行。
- 已验证 Join 的关系边默认生成视图，继续输出 `EDGE_ID`、`SOURCE_ID`、`TARGET_ID`，可直接被属性图的 `KEY`、`SOURCE KEY`、`DESTINATION KEY` 引用。
- 无稳定节点主键时保留原有 CTAS 表回退策略。
- 重建清理同时兼容历史同名表和新视图，确保旧的 `ONTO_NODE_*` 或 `ONTO_EDGE_*` 表可以原位迁移为同名视图。
- 保存 DDL 快照时同步本体构建方式为实际采用的 `VIEW` 或 `TABLE`；模板对象按名称覆盖 LLM 返回的同名 `CREATE TABLE`，避免最终脚本包含冲突对象。

### 验证结果
- `python -m py_compile backend/app/services/ddl_service.py backend/app/api/ddl.py` 通过。
- `git diff --check` 通过。

### 遗留问题与下一步建议
- 视图键的唯一性由生成的去重查询保障；若用户手工修改视图 SQL，应保持节点键非空且唯一、边键唯一，以符合 Oracle Property Graph 的图键语义。

## Oracle 视图去重列标识符修复

### 背景
- 首次生成的视图使用了 `__ONTO_KEY_RN` 作为窗口函数别名；Oracle 未加引号的标识符必须以字母开头，导致 `ORA-00911`。

### 改动与验证
- 将内部去重列统一改为合法的 `ONTO_KEY_RN`，外层过滤条件同步更新。
- `python -m py_compile backend/app/services/ddl_service.py` 与 `git diff --check` 通过。

## DDL 历史明细空白修复

### 背景
- 2026-08-17 03:52:49 的异步 DDL 任务因边 Join 预检查出现 `ORA-00904: SRC.CONTAINER_CODE_PREFIX` 失败，但 `sys_ddl_statement_log` 没有明细。
- 原因是预检查异常发生在执行循环的结果落库之前，后台任务仅更新了汇总失败状态。

### 具体改动
- 边 Join 预检查异常改为对应 SQL 的 `failed` 明细，后续 SQL 可继续记录。
- 后台任务先提交逐 SQL 执行结果，再尝试同步部署状态；同步失败不再清空执行历史。
- 后台任务出现其他未捕获异常时，自动保存一条 `DDL TASK` 失败明细。
- 对已有的失败历史记录，若没有历史明细，查询接口返回一条包含原始任务错误的兜底明细，避免页面空白。

### 验证结果
- `python -m py_compile backend/app/services/ddl_service.py backend/app/api/ddl.py` 与 `git diff --check` 通过。
