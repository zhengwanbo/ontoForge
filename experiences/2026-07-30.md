## 2. 形成 Guide 结构化本体生成改造设计文档
### 背景
- 在整理完当前 Guide 执行链后，需要进一步把“按问卷 + DDL + 规则 SQL 先做结构化分析，再生成 canonical 本体与标准化视图”的改造思路固化成正式设计文档。
- 目标不是立即改代码，而是先产出一份后续可按阶段执行的实施依据，避免后续修改时再次回到泛泛讨论。

### 改动文件列表
- `docs/guide-structured-ontology-refactor-design.md`
- `experiences/2026-07-30.md`

### 设计结论
- Guide 需要新增 `structured_domain_pipeline` 策略，作为后续默认主链路；旧 `llm_first` 暂时保留以兼容其他分析域。
- 后端链路应拆为：
  - 输入资料整理
  - 结构化分析
  - 范围确认
  - canonical 本体生成
  - 标准化视图计划生成
  - LLM enrich
  - blueprint 落库
  - 可选应用
- 结构化分析阶段应显式产出：
  - `document_facts`
  - `rule_analysis`
  - `schema_analysis`
  - `focus_scope`
  - `metric_semantics`
- 当前 TAMS SFR 场景的核心对象、关系、标准化视图不应继续依赖 LLM 自由生成，而应由领域模板生成器稳定输出。
- 前端 Guide 需要从单页提交改成四步式流程，并增加“分析结果确认”页。
- DDL 与映射阶段后续要优先消费 `view_plan`，让标准化视图计划成为正式输入。

### 建议修改顺序
- 第一阶段：扩 `OntologyGuideGenerateRequest` 和 blueprint payload，加入策略开关与新分析字段。
- 第二阶段：在 `OntologyGuideService` 中实现结构化分析阶段。
- 第三阶段：新增 `domain_ontology_generators/tams_sfr_generator.py`，稳定产出 canonical model 与 view plan。
- 第四阶段：收缩 `llm_service` 的职责，使其只负责 enrich。
- 第五阶段：改造 `OntologyBuild.vue` 为分步式 Guide UI。
- 第六阶段：让 `DDLService` 与映射页消费 `view_plan`。

### 验证结果
- 本次仅新增设计文档与经验记录，没有修改业务代码，也未执行构建或测试。
- 文档内容基于当前以下实现文件整理并约束：
  - `backend/app/services/ontology_guide_service.py`
  - `backend/app/services/llm_service.py`
  - `backend/app/services/ddl_service.py`
  - `backend/app/schemas/schemas.py`
  - `frontend/src/views/ontology/OntologyBuild.vue`
  - `frontend/src/views/mapping/DataMappingOperation.vue`

### 下一步建议
- 后续编码时，严格按本文档的“推荐实施步骤”逐阶段推进，不要一开始同时改 Guide、映射和 DDL 三条线。
- 第一轮应优先完成后端结构化分析与 canonical model 生成，前端和 DDL 消费可以滞后半步接入。

## 6. 完成 Guide 结构化改造阶段 4：LLM 职责收缩为 enrich
### 背景
- 阶段 3 虽然已经接入领域模板生成器，但 `structured_domain_pipeline` 仍通过 `_generate_with_llm_first()` 获取前置上下文，实际仍依赖旧链路生成实体/关系/部署结果。
- 阶段 4 的目标是彻底收紧 LLM 职责，让 structured 分支只把 LLM 用于：
  - 范围说明文档 enrich
  - canonical model enrich
  - view plan SQL / purpose enrich

### 改动文件列表
- `backend/app/services/llm_service.py`
- `backend/app/services/ontology_guide_service.py`
- `experiences/2026-07-30.md`

### 具体改动
- `llm_service.py` 新增 3 个 enrich 接口：
  - `generate_structured_ontology_scope_document()`
  - `enrich_structured_canonical_model()`
  - `enrich_structured_view_plan()`
- 这 3 个方法都明确限制：
  - 不能新增新的核心对象和关系
  - 不能重规划 view plan
  - 只能对现有结构做说明、证据补充和 SQL 草案 enrichment
- `OntologyGuideService` 新增 `_prepare_guide_generation_context()`：
  - 将 Guide 的公共准备逻辑独立出来
  - 供 structured 分支直接使用
  - 不再借道 `_generate_with_llm_first()` 获取上下文
- `structured_domain_pipeline` 现已改为：
  - 先调用 `_prepare_guide_generation_context()`
  - 再做结构化分析
  - 再生成 `canonical_model` 与 `view_plan`
  - 再调用上述 3 个 enrich 接口
  - 最后合并 enrich 结果并持久化 blueprint
- 新增 merge 方法：
  - `_merge_canonical_model_enrichment()`
  - `_merge_view_plan_enrichment()`
- 这些 merge 方法确保：
  - LLM enrich 只补充字段，不会把领域模板的核心骨架覆盖坏
  - view plan enrich 只更新已有 view 的 purpose / deploy / sql / note 等内容

### 当前 structured 分支行为变化
- 不再依赖 `_generate_with_llm_first()` 产出实体/关系/部署主结果。
- 顶层 `entities` / `relations` 现在来源于：
  - 结构化分析
  - 领域模板生成器
  - LLM enrich 合并
- `ontology_design_document` 现在来源于 structured scope enrich，而不是旧的范围生成链路。
- `llm_enrichment` 中新增了结构化 enrich 相关模式与模型信息：
  - `scope_document_generation_mode`
  - `canonical_enrichment_generation_mode`
  - `view_plan_enrichment_generation_mode`

### 验证结果
- 执行：
  - `python -m py_compile backend/app/services/llm_service.py backend/app/services/ontology_guide_service.py backend/app/services/domain_ontology_generators/tams_sfr_generator.py backend/app/api/ontology.py backend/app/schemas/schemas.py`
- 结果：
  - 后端语法检查通过。
  - structured 分支已不再通过旧 LLM-first 链路生成本体骨架。

### 结论
- 阶段 4 已完成，当前 Guide 的 structured 分支已经达到：
  - 核心对象/关系/视图骨架由结构化分析 + 模板生成决定
  - LLM 只负责 enrich、说明、证据表、joinCondition、edgeSql / view sql 草案
- 下一阶段可以开始改前端 Guide 对话框，把“资料输入 -> 分析结果确认 -> 本体预览 -> 视图计划与应用”的四步流程接上。
