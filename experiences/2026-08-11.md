## 基于知识地图的通用 Agent 图查询规划

### 背景

- 用户要求 Agent 不依赖不断新增的业务硬编码模板，而应依据用户问题和实时 Oracle Property Graph 知识地图自动识别节点、关系、路径、属性和精确过滤条件。

### 改动文件列表

- `backend/app/services/agent_service.py`
- `backend/tests/test_agent_skill_package.py`
- `experiences/2026-08-11.md`

### 具体改动

- 托管 Skill 对话改为“拓扑规划优先、受控模板兜底”：先将实时图的节点标签、属性和边关系交给 Agent 规划器，再在代码侧根据计划编译 `GRAPH_TABLE` SQL；仅当规划结果无效时使用已有五层包装、生产追溯或出库到经销商模板。
- Agent 只允许输出 JSON 查询计划（起点节点、过滤属性和值、目标节点和目标属性），不接受或执行模型直接生成的 SQL。
- 编译器严格校验所有节点、属性、关系边来自实时拓扑；用有向 BFS 搜索起点到目标节点的路径，按每条路径生成 CTE 并以根节点主键关联结果。
- 过滤值必须精确出现在当前问题或会话上下文，并且只能使用受限字符集；无法验证、没有目标路径或无精确标识时拒绝通用计划并进入受控兜底，避免无边界图遍历与 SQL 注入。
- 新增编译器回归测试，验证基于 `BOTTLECODE → PRODUCTIONBATCH → FACTORY` 知识地图生成两跳路径及精确瓶码过滤。

### 验证结果

- `cd backend && python -m unittest tests.test_agent_skill_package tests.test_mapping_oracle_graph` 通过（12 tests）；仅输出既有 Pydantic `schema` 字段命名警告。

## 当前问题主导的会话图查询与澄清

### 背景

- 用户要求通用图规划器以当前问题作为唯一回答目标，最近 5 条历史消息仅作为模型寻找相关标识和解析指代的辅助材料；当前问题不明确时应先澄清，不能任意复用历史查询。

### 改动文件列表

- `backend/app/services/agent_service.py`
- `backend/tests/test_agent_skill_package.py`
- `experiences/2026-08-11.md`

### 具体改动

- 规划器与分析 Agent 的提示词均明确：历史对话只能用于解析指代或寻找当前问题相关标识，不能复用历史 SQL、字段、表格或结论替代当前回答。
- 对“继续”“继续查询”“这个怎么样”等无明确对象、关系或标识的纯含糊问题，Agent 持久化一条澄清回复，不执行 Oracle Graph SQL，也不继承上一轮查询结果。
- 对“查询该瓶码的质检记录”这类对象意图明确但省略编码的问题，仍可从最近 5 条上下文解析瓶码，并以当前的质检意图重新生成图查询。
