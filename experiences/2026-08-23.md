## DDL 生成前结构化错误定位与映射跳转

### 背景

DDL 生成失败时，页面此前只显示一条笼统错误文本，用户无法确认是哪个实体、属性或关系缺少主键、数据源映射、英文边表名或 Join 配置，也无法直接进入对应的数据映射位置修复。

### 改动文件

- `backend/app/services/ddl_service.py`
- `backend/app/api/ddl.py`
- `frontend/src/views/ddl/DDLManage.vue`
- `frontend/src/views/mapping/DataMapping.vue`
- `frontend/src/api/index.ts`
- `backend/tests/test_ddl_preflight_validation.py`

### 实施内容

- 增加 DDL 生成前完整校验，一次收集全部阻断项：实体主键、实体源数据映射、关系边表英文名、关系端点、两端主键、直接 Join、关系表模式所需字段等。
- 每一项返回结构化的错误码、对象名称、具体原因、修复动作和前端跳转目标；API 以可解析的错误详情返回，不再只保留单条 ValueError 文本。
- DDL 页面展示“DDL 生成前校验问题”表格，点击“去修复”跳转至数据映射管理的对应实体；关系问题同时带上 `relation_id`，在关系表中以红色高亮显示该行。
- 调整通用 API 错误提示，支持结构化 `detail.message`，避免显示为 `[object Object]`。

### 验证结果

- `cd backend && python -m py_compile app/api/ddl.py app/services/ddl_service.py`：通过。
- `cd backend && python -m unittest tests.test_ddl_preflight_validation tests.test_ontology_guide_prompt_compaction`：11 项通过。
- `cd frontend && npm run build`：通过；仅保留既有构建产物体积提示。
- `git diff --check`：通过。

## DDL 结构化校验异常类导入修复

### 背景

DDL 生成接口捕获 `DDLPreflightValidationError` 时，函数内仅导入了 `DDLService`，导致校验失败路径触发 `NameError`，无法返回结构化错误清单。

### 改动与验证

- 在 `backend/app/api/ddl.py` 的 `generate_ddl` 函数内同时导入 `DDLService, DDLPreflightValidationError`。
- `python -m py_compile app/api/ddl.py app/services/ddl_service.py` 通过。
- `python -m unittest tests.test_ddl_preflight_validation` 通过。

## 数据映射管理中的映射关系检查

### 背景

用户希望在进入 DDL 生成前，直接在“数据映射管理”检查全域实体与关系映射是否达到 DDL 标准，并能定位到需要人工确认或修复的位置。

### 改动文件

- `backend/app/api/mapping.py`
- `frontend/src/api/index.ts`
- `frontend/src/views/mapping/DataMapping.vue`

### 实施内容

- 新增 `POST /mapping/domains/{domain_id}/ddl-readiness-check`，复用 `DDLService.validate_ddl_readiness`，确保映射页与 DDL 页完全使用同一校验标准。
- 数据映射管理顶部新增“映射关系检查”按钮；结果按实体/关系列出主键、属性来源、边表英文名、Join 和关系表模式配置等问题。
- 点击每项操作会切换到对应实体；关系问题会额外高亮对应关系配置行，用户可直接修改、保存后重新检查。

### 验证结果

- `cd backend && python -m py_compile app/api/mapping.py app/services/ddl_service.py`：通过。
- `cd backend && python -m unittest tests.test_ddl_preflight_validation tests.test_ontology_guide_prompt_compaction`：11 项通过。
- `cd frontend && npm run build`：通过；仅保留既有构建产物体积提示。
- `git diff --check`：通过。
